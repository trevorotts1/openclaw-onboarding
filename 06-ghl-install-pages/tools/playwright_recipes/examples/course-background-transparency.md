# Inactive course Background Image transparency

Compile `courses.configure_ui` with the exclusive `background_transparency`
configuration in the companion JSON. It uses the maintained
`native_course_theme_media` action and the same tenant guard, writer lease,
pre-write intent and uncertain-write journal as background uploads. Replace all
example identities, title, URL and expected percentage with current inventory.
Do not combine it with an upload, another theme edit or publication.

This authors the native Layout > Background Image > Transparency control.
Live capture on November 9, 2026 established matching fill-width and handle-left
integer percentages, ArrowLeft/ArrowRight increments of one point, and the
0/100 endpoints. Home does not change this control. The writer uses only those
measured arrow keys, one key per exact delta; it never writes DOM styles or
assumes a missing ARIA value. The measured handle focus stacking transition
between z-index 0 and 1 is ignored; any other stacking value is refused. The
existing image URL, all other slider properties, active theme, text/palette/fonts and Body
inventory/content are preserved. Unsupported, fractional, stale or disagreeing
readback stops before another key or Save.

The expected and desired percentages must be different integers from 0 through
100. The handler saves the inactive template once and independently reopens
that exact template before completing. The typed receipt binds the original
configuration, retained background URL and authored percentage on both first
completion and replay. It keeps `functional_verified:false` and
`activation_performed:false`; source tests and UI control capture are not a
claim of final native Python/client or learner acceptance. Image removal and
Hero overlay transparency remain separate unsupported operations.
