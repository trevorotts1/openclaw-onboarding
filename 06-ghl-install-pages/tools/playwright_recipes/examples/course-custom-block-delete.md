# Delete one existing inactive-template Custom Block

Use `courses.configure_ui` with exclusive `custom_blocks.deletion`, explicit
`action:"delete"` and the exact existing Custom Block UUID. Supply its complete
current text/button values, original rich HTML, image URL and the complete
sidebar UUID/type/order inventory. Replace every example identity and value
with independently read client inventory. Never use this mode for Category,
Text, Image or Video Blocks, image removal, bulk deletion or a mixed edit job.

The existing `native_course_blocks` action dispatches to the maintained deletion
leaf. Before the native Delete Block action and again before Confirm, the
writer binds the exact selected Custom Block inspector, preview UUID/type/order
and expected content. The second check reads the existing Body and inspector;
it never clicks behind the confirmation dialog. It requires the captured exact
confirmation heading, data-removal warning and Cancel/Confirm controls.

After Confirm the complete sidebar and rendered Body must be exactly the old
inventory minus that UUID. Surviving supported blocks retain their content and
media. Captured theme/header/hero/sidebar controls, background and Hero/Instructor
media remain unchanged; unsupported hidden/color-mode section shapes refuse
before deletion because their complete media state cannot be vouched for.
Unrelated unsaved edits also stop before opening the destructive dialog.

The writer saves the inactive template once and independently reopens the exact
course/template to verify removal and every preserved snapshot. Original input
hash, removed UUID and exact survivor order bind first completion and replay.
An uncertain journal never retries Delete/Confirm. Template activation,
publication and learner effects remain unperformed; the receipt explicitly
keeps functional proof pending. Native control capture and source tests do not
constitute final native Python/client acceptance.
