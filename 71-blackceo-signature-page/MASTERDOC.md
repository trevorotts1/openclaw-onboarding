# BlackCEO Signature Page — Skill 71 Master Integration Contract

## Purpose

Skill 71 is the OpenClaw-native home of the BlackCEO **single-page** Signature Page system created and calibrated before repository integration. It preserves the Standard v6 and Long-Form v6 copy systems, Production/QC SOP, Image Intelligence v5 + Visual Reference Guide, Secret Super Sauce, and three page-level Creative Direction libraries.

## Boundary with existing page/funnel skills

| Request | Canonical owner |
|---|---|
| BlackCEO single landing / opt-in / event / challenge / booking / squeeze / focused conversion page | **Skill 71** |
| Multi-step 3/5/7 Signature Funnel with checkout/upsell/downsell/OTO | **Skill 49** |
| Direct-Response/VSL asset stack, high-ticket, bump, A/B sales-page system | **Skill 56** |
| Animated/cinematic scroll experience | **Skill 62** |
| Generic multi-page marketing website | Website-craft + Web Development |

A plain request to "build me a landing page" should reach Skill 71 through the Web Development / Landing Page Specialist path. A user does not need to know the skill number or name.

## Department ownership

Primary department: `web-development`
Primary role: `landing-page-specialist`

This uses the repo's existing native-skill invocation architecture; do not create a new department or duplicate role merely for Skill 71.

## Execution seams

- Skill 71 owns page methodology, page copy system, visual plan, image-prompt intelligence, stage/QC rules, and final page artifact contract.
- Skill 66 owns Kie.ai image-model routing/validation/dispatch/QC.
- Skill 63 owns Agnes image execution when selected.
- Skill 6 owns GHL media/page delivery.
- Skill 8 owns Vercel setup/deployment prerequisites when used.
- Existing browser-management rules own browser automation.

## Runtime policy

Use the client's own configured providers and credentials. Never bundle credentials. Never duplicate provider clients that the onboarding repo already owns. Respect paid-call approval/budget rules before spend.

## Methodology preservation

The detailed methodology lives in `references/`. Repository integration may change paths, routing, adapters, and delegation seams; it must not silently rewrite the BlackCEO copy, visual, or QC system.
