## Every stop explained

**Binding (owner order 2026-11-20).** When the work stops, refuses, holds or
waits, the client gets four parts in plain, fifth-grade words, never a dead
stop: **what happened** (with the real numbers), **why this rule exists**
(what it protects the client from), **what will fix it**, and **2-4 numbered
choices**, one of which is always the agent doing the work. Build the message
with `loud_failure.explain_stop(reason_code, facts, envelope)` (it reads this
table) and send its `message` field; never type the code, a file path or an
error trace to the client. `{name}` is filled from the stop's own facts and
`{name:words}` falls back to the words after the colon. A new client-facing
stop ships with its row here: `scripts/core/test_stop_explanations_s75.py`
fails otherwise. Choices are split with `<br>`.
