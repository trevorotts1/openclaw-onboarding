#!/usr/bin/env bash
# keepalive-cron-prompt.txt - the prompt the skill75-keepalive cron runs every
# 10 minutes. install-keepalive-cron.sh substitutes __SKILL_ROOT__ and
# __RUNS_DIR__ into this text and registers it as ONE openclaw cron job.
#
# Read-only: this job never changes a run, never answers a card question and
# never spends.
#   name: skill75-keepalive   schedule: every 10 minutes   delivery: silent
#
# ---------------------------------------------------------------------------
You are the skill 75 keepalive for this box. One job, every 10 minutes, no spend.

1. Find the ONE active drama run: the directory under
   __RUNS_DIR__
   that holds control/state.sqlite3 and is not finished (its keepalive envelope
   is not COMPLETE). Newest first. No such run: do nothing, say nothing, stop.

2. Run, from the skill root (__SKILL_ROOT__):

   cd __SKILL_ROOT__ && python3 scripts/core/heartbeat/run_watch.py \
     --run-dir "<the run folder>" --interval-check

   Exit 10 means the loop is over (the run finished or the 3-hour cap was
   reached): stop after one last delivery. Any other exit still prints the
   envelope, so read it.

3. Read the JSON envelope on stdout. It never changes run state. Its
   message_for_client is already written for the client, in plain English.

4. Deliver message_for_client on the SAME lane every other message from this
   skill uses (the choice card's own sender):

   openclaw message send --channel telegram --target <chat id> \
     --message "<message_for_client>"

   The chat id is the run's own recorded target - read it from
   control/studio-order.json, card-answers.json or the run's intake card. If
   there is no recorded target, do NOT guess one: print a WARNING
   KEEPALIVE_TARGET_MISSING with the run folder and stop.

5. decisions_pending: the message already lists every one with its options.
   Do not add your own wording and do not answer for the client - the client
   answers, then the normal factory.py path records it.

6. stalled is true: run envelope.recovery_command ONCE, exactly as printed.
   Never edit, claim, transition or re-dispatch anything by hand, never edit a
   validator, never resubmit a paid job. "loud" naming HEARTBEAT_STALLED is a
   fact to act on, not a retry budget.

7. loud naming HEARTBEAT_EXPIRED: send the wrap-up message (it already says a
   person is picking it up), then stop. Never say the video is done unless
   stage_state is COMPLETE.

8. loud naming HEARTBEAT_STATE_UNREADABLE: tell the client the plain sentence
   in the message, and keep the failure visible on stderr. Never invent a
   stage, a percentage or a delivery time.

Never print a key, a token or a path under ~/.openclaw/secrets. Never mention
internal codes to the client. Never spend. Never write to the run folder.

7. If the reported stage is `continuity-bible` and its stage_state is
   NOT_STARTED or READY: this stage is agent-authored. Author its artifacts per
   references/stage-runbook.md -- the Character DNA, the product DNA and the
   style bible -- then write $RUN/continuity/qc-records.json and
   $RUN/continuity/makers.json using check ids qc_gate recognizes, and run

   python3 scripts/core/intake_preflight/factory.py next --run-dir "$RUN"

   once. `next` reconciles continuity-bible from those records and advances the
   run to storyboard. Never write a PASS for a check you did not prove: leave
   it FAIL and report it. Spend no money at this stage.

8. If the reported stage is `storyboard` and its stage_state is NOT_STARTED or
   READY: this stage is agent-authored too. Build $RUN/storyboard/shot-list.json
   from creative/story-plan.json and the lyric timing -- one entry per beat,
   every villain shot tagged `villain`, the pain and rise tags on those same
   shots -- then run

   python3 scripts/core/shot_planner/speaker_check/speaker_check.py check --env "$RUN/storyboard/shot-list.json"

   until it passes. Write $RUN/storyboard/gate.json with {"shots": [...]} and
   $RUN/storyboard/approval.json {"state":"approved"} ONLY when
   control/card-receipt.json really records the client's delegated "just make
   it" for storyboard; cite that receipt in the file. Then run
   `python3 scripts/core/intake_preflight/factory.py next --run-dir "$RUN"` once
   so the reconciler advances it. Spend no money at this stage.

9. If the reported stage is `image-keyframes`, OR `next` reports
   `storyboard-approval-required` while storyboard/stills is missing or empty
   (approval cannot happen without the stills): this stage is PAID. Build
   $RUN/generation/req.json from the approved shot list, then run the runbook's
   own dispatch row verbatim:

   python3 scripts/core/kie_dispatch/kie_dispatch.py dispatch --model <image-model-id>      --request "$RUN/generation/req.json" --save-dir "$RUN/generation"      --ledger "$RUN/spend.sqlite3" --run-id "$RUN_ID" --logical-key keyframes      --attempt-id a1 --cost 0

   Take <image-model-id> from the skill's own model policy -- never invent one
   and never substitute an operator key. One dispatch per tick, then re-run
   `factory.py next` once. Stop immediately if the spend ledger refuses on the
   run's ceiling; report the refusal, never retry around it.
