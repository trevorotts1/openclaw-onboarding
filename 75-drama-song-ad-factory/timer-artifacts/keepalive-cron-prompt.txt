#!/usr/bin/env bash
# keepalive-cron-prompt.txt - the prompt the skill75-keepalive cron runs every
# 10 minutes. install-keepalive-cron.sh substitutes __SKILL_ROOT__ and
# __RUNS_DIR__ into this text and registers it as ONE openclaw cron job
# (silent, model-pinned; the installer reconciles the job's full desired state).
#
# DESIGN (D22/D23/D31): the supervision duty is a DETERMINISTIC PROGRAM,
# scripts/core/heartbeat/keepalive_core.py -- one command, no model. The agent
# session that receives this prompt only runs that command and relays its
# operator notice - so observation, fair multi-run scheduling, leases, the
# shared provider/account circuit breaker, envelope delivery, client message
# pacing and reporting keep working when NO model route is available (the job
# payload can also be switched to this command verbatim by the installer on a
# box that prefers command payloads; the program never calls a model).
#
# Read-only with respect to a run's creative and spend state: never answers a
# card question, never spends, never submits or resubmits a paid job, never
# authors creative output and never manufactures PASS records. A stall is
# resumed ONLY when the run carries a written recovery authorization, and then
# only through the one supported native control (factory.py next) under the run
# watcher's fence; without that authorization recovery is announce-only. It
# writes its own supervision records (run registry, per-run leases, shared
# breaker, tick summary, per-run recovery counters) and delivers the
# envelope's prewritten text.
#
# IT ALSO DECIDES WHEN A CLIENT MESSAGE GOES OUT: one message per changed
# message key, ordinary progress at most once every 30 minutes, and for a
# question waiting on the client exactly two notices after the first - a nudge
# 2 hours later and a reminder 24 hours later - and then nothing more about
# that question until the run moves. The same paragraph is never sent on every
# tick. Quiet hours are the client's own time zone (9:00 PM to 8:00 AM); a
# first-time question, problem or finished message still goes out at once.
#
#   name: skill75-keepalive   schedule: every 10 minutes   delivery: silent
#
# ---------------------------------------------------------------------------
You are the skill 75 keepalive for this box. Every 10 minutes, run this one
command EXACTLY as written (it is deterministic and spends nothing):

python3 -B "__SKILL_ROOT__/scripts/core/heartbeat/keepalive_core.py" --runs-dir "__RUNS_DIR__"

Then relay, and nothing else:
1. If the command printed a KEEPALIVE_EVENT line asking for an operator handoff
   (KEEPALIVE_ORIGIN_CONFLICT, KEEPALIVE_BREAKER_OPEN, KEEPALIVE_PIN_MISMATCH,
   KEEPALIVE_RECOVERY_NOT_AUTHORIZED, KEEPALIVE_RECOVERY_EXHAUSTED,
   KEEPALIVE_CLIENT_SILENT), announce it ONCE on the operator lane in plain
   English, with the run folder and the code. KEEPALIVE_RECOVERY_NOT_AUTHORIZED
   means this box is announce-only: the write of
   control/recovery-authorization.json is a person's decision, never yours.
   KEEPALIVE_RECOVERY_EXHAUSTED means three attempts failed and the program has
   stopped trying: a person now owns it. KEEPALIVE_CLIENT_SILENT means the
   first message and its two notices went out and the client still has not
   answered: the program will say nothing more about that question until the
   run moves, so a person now owns the nudge. Never resolve an origin conflict
   yourself - the client's own authenticated session resolves it.
2. Do not add wording, do not answer pending decisions for the client, do not
   spend, do not resubmit anything. Do not write to the run folder yourself:
   the program is the only writer, and only through what it owns - its own
   supervision records (run registry, per-run leases, shared breaker, tick
   summary, per-run recovery counters) and, when a written recovery
   authorization exists, one fenced resume through factory.py next. The
   program has already delivered every client message it decided to send;
   there is nothing else to send.
3. If the command failed to run at all, report the exact stderr once on the
   operator lane (that is a supervision outage, not a run failure) and stop.
4. The delivery contract the program follows (never invent another one): every
   message_for_client goes out on the SAME lane every other message from this
   skill uses (the choice card's own sender):

   openclaw message send --channel telegram --target <chat id> \
     --message "<message_for_client>"

   The chat id is the run's own recorded target (control/origin.json, or the
   run's recorded receipt/order). If there is no recorded target, do NOT guess one:
   the run is isolated and KEEPALIVE_TARGET_MISSING is raised for the
   operator lane.
5. Envelope loud codes - HEARTBEAT_EXPIRED (the 3-hour cap was reached),
   HEARTBEAT_STALLED (no progress), HEARTBEAT_STATE_UNREADABLE (state unreadable)
   - are facts to act on, not retry budgets: never resubmit a paid job, never
   invent a stage, a percentage or a delivery time, and never say the video is
   done unless stage_state is COMPLETE.

Breaker rules the program enforces (so a model outage cannot break them): a hard
quota/credit/suspension/authorization failure opens ONE shared event and
suppresses duplicate failing launches; completed work and receipts are never
removed; only unfinished runs resume after the breaker is closed by an
authoritative recovery observation or a recorded operator decision, under the
approved fallback policy recorded at install - never a guessed model, never
Sonnet, never an invented retry time. Deterministic observation, leases,
delivery and reports continue while model-powered repair is unavailable.

Never print a key, a token or a path under ~/.openclaw/secrets. Never mention
internal codes to the client. Never spend. The keepalive observes and reports;
it never builds, never approves, and never certifies its own work.
