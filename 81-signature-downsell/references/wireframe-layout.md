# Downsell Page Layout - Wireframes and Mockups (Skill 81)

Status: build candidate. Structure only. The sheet language (section chips, name tabs, printed type specs, labelled image plates, filled buttons, contiguous bands) and the colors are Skill 71's: every wireframe and mockup is drawn in the client's own brand colors, never in grey line work. The machine form of this page is `71-blackceo-signature-page/references/page-structures.json`, role `downsell_1`; the wireframe lines are in `71-blackceo-signature-page/references/wireframe-build-spec.json` under `page_profiles`. This file is the plain description of the same bands.

## The page in one view

Eight bands, one per numbered section, never merged. Every band carries the one purchase button and, beside it, the decline button. The decline button is an outlined secondary button of the same height: a real choice, never a text link. Money terms sit at body size next to the button in every band. The first screen tells the visitor their original order is confirmed and safe. Nothing on the page may suggest the original purchase is at risk.

Every page of this role is built the same way as the landing: Design Board for the downsell role first approved by the client, desktop and mobile, design style A, B or C chosen for the client (circle photos are transparent-corner PNGs), composition variety across the bands, the hypersaturated image grade, references used for structure only, one long top-to-bottom review PDF per stage, and overview boards.

## Rules the layout keeps

1. The three problem bands (2, 3, 4) never share one geometry and never render as three identical cards.
2. Band 7 shows what is not included as honestly as what is.
3. Band 8 lists exactly seven optional benefits the visitor will not receive; it never reads as a loss of the original purchase.
4. Every state has a desktop and a mobile design before install (see `design-profile.md`).
5. Nothing in this file is copy. The words come from the approved page copy; the layout names bands, not sentences.
