# WF11-CR01 — reconcile the WF10 assumed operation ids to the WF00-CP01 frozen rows

Status: FIXED in this lane (`ghl-hybrid/r3-20261108/wf11` → corrected below), no
WF00 change requested: the rows already exist and are correct.

## What WF11 found after merging WF00 (293a79b90) and WF10 (20b29c622)

`public/community_social.py` declared three Community operation ids that WF10
wrote before WF00 froze the rows (its own docstring said WF00 owns the ids and
the ids were pending, CR `lanes/GHL-010-lane/change-requests/1.md`). WF00-CP01
then froze the same three routes under different ids. Proven against the real
registry, not by reading:

```
OK    accounts.list     -> social.accounts.list
MISS  members.list      -> social.community.users.list
MISS  members.validate  -> social.community.group_users.validate
OK    posts.create      -> social.posts.create
OK    posts.list        -> social.posts.list
OK    posts.get         -> social.posts.get
MISS  comments.create   -> social.comments.community.create
OK    comments.list     -> social.comments.list
```

## Resolution (content identical, only the ids drifted)

| WF10 assumed id | WF00-CP01 frozen id | method | path | scope |
|---|---|---|---|---|
| `social.community.users.list` | `social.community.accounts.users.list` | GET | `/social-media-posting/{locationId}/community/accounts/{accountId}/users` | `socialplanner/oauth.readonly` |
| `social.community.group_users.validate` | `social.community.authors.validate` | GET | `/social-media-posting/{locationId}/community/groups/{groupId}/users/{contactId}/validate` | `socialplanner/account.readonly` |
| `social.comments.community.create` | `social.community.comments.create` | POST | `/social-media-posting/comments/community` (tenant in QUERY) | `socialplanner/comments.write` |

`public/community_social.py::OPERATION_IDS` and its contract test now carry the
frozen ids; `PENDING_OPERATION_ROWS` is empty because nothing is pending.
`test_a14_every_consumer_operation_id_is_a_frozen_wf00_row` and
`test_a14_frozen_community_rows_carry_the_documented_facts` fail if either side
drifts again.
