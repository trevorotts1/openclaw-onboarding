# WF11-CR02 — WF10-CP01 does not expose the created post id, the created comment id, or a post read

Status: OPEN — change requested against WF10 (adapter owner). WF11 does NOT
invent the missing values; it reports them as named gaps.

## Facts (read from the published surface, `community_social.py` WF10-CP01)

1. `PostReceipt` carries `result: OperationResult`, `lifecycle: PostLifecycle`,
   `request: PlatformRequest`, `deduplicated: bool`. `OperationResult` is the
   GU-004 receipt envelope (status, receipt_id, fingerprints, readback,
   evidence); it carries no provider response body, so the created post id is
   not reachable from a receipt.
2. `CommentReceipt` carries `result`, `plan`, `attachments_rendered`. Same
   limitation for the created comment id.
3. `CommunitySocialAdapter` exposes `list_connected_accounts`,
   `list_community_accounts`, `list_members`, `iter_members`, `validate_author`,
   `require_valid_author`, `create_post`, `publish_plan`, `create_comment`,
   `list_comments`. There is **no** single-post read (`social.posts.get` is
   frozen in `operations.py` and named in `OPERATION_IDS["posts.get"]`, but no
   adapter method issues it).

## Why it matters to Skill 35

- A comment needs the INTERNAL post id. Skill 35 takes it from the operator (or
  a later reconciliation), not from the create receipt.
- A caller that wants the provider post id (permalink, later edit, cross-system
  linkage) has no supported read.

## Requested change (smallest honest surface)

- Add `post_id: str | None` to `PostReceipt`, populated from the create response
  when the response carries an id, and from the matched readback record when it
  does not.
- Add `comment_id: str | None` to `CommentReceipt` on the same rule.
- Add `CommunitySocialAdapter.get_post(*, tenant, post_id, attempt=1)` issuing
  the frozen `social.posts.get` row (currently unused) so a readback is
  explicit.

## What WF11 does until then

- `Wf10CommunityAdapter.create_post` returns `post_id_gap=post_id_not_exposed_by_wf10_cp01`;
  the consumer receipt reports `post_id: null` and `published` only from the
  lifecycle.
- `Wf10CommunityAdapter.create_comment` returns
  `comment_id_gap=comment_id_not_exposed_by_wf10_cp01`; the consumer reports
  `comment_id: null` with state `submitted` because the provider accepted it.
- `Wf10CommunityAdapter.get_post` raises `post_read_unavailable` naming this CR.
